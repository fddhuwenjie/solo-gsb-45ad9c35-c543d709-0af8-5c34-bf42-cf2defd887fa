# 小剧场排练 · 剧本换版

一个给小剧场排练用的剧本工作稿 / 发布版管理网页：

- 技术栈：**Python（Flask）+ SQLite + 原生 JavaScript**（无前端框架、无构建步骤、无外部 CDN）。
- 工作稿由有序台词组成，每句台词有 **永不复用的编号**、角色、正文。
- **角色页**：只看本角色的台词，每句带「紧前一句」提示，可给自己的台词写排练笔记。
- **角色确认**：角色在角色页核对自己所见的**台词编号与顺序、正文、紧前提示和笔记**后点「确认本页所见内容」；首页列出每个当前有台词角色的确认状态，可一键进入待确认角色页。
- 确认**只对该角色当时可见的内容有效**：这些内容与确认时不同就重新显示「待确认」，其他角色的无关改动不影响已确认状态（页面会逐条标出正文 / 紧前提示 / 笔记 / 顺序变化）。
- **改词建议**：角色在自己角色页对自己的台词提交改词建议（记录台词编号、提出时的角色与原文、拟替换正文），**不直接改稿**；编辑在「改词审阅」页并排查看**提出时原文 / 当前正文 / 拟替换正文**后集中采纳或驳回。
- 提交建议必须带**页面所见修订号**，过期则拒绝（提交建议不推进修订）。采纳时在**同一数据库事务**内替换正文、推进工作稿修订号、标记建议已采纳；台词**已删除 / 已改派 / 原文已变**时采纳报冲突，工作稿不变且建议保留待处理；其他台词或笔记的改动不妨碍采纳。驳回只改变建议状态，已处理建议不能重复处理。
- 采纳替换正文后，受影响角色的确认状态按既有规则自动更新（正文或紧前提示变了就待确认），发布闸门随之自动生效。
- 提交确认必须带上**页面所见的工作稿修订号**，过期则拒绝；编辑台词和笔记仍遵循原有的修订号规则（成功一次修订 +1，确认本身不推进修订）。
- **发布闸门**：发布在同一个数据库事务里核对所见修订号、**所有当前角色的确认状态**以及要冻结的台词和笔记；有待确认角色就整次拒绝并列出角色，绝不留下部分发布版。没有台词时确认清单为空，可直接发布。
- **编辑工作稿**：增删、改派角色、改词、上移 / 下移重排，全部暂存后一次保存。
- **提示随顺序即时重算**；**笔记始终跟随原台词编号**，重排、改词都不会丢。
- **删除或改派仍带笔记的台词，整次拒绝**，并明确指出要先到哪个角色页处理笔记——笔记不可能落到别的台词或角色。
- 修改工作稿不影响任何已发布版；**发布**把所有角色页和笔记冻结进同一个修订快照，旧版永远可以打开。
- 编辑台词 / 笔记必须提交「所见工作稿修订号」：过期修改**整次拒绝**，不会覆盖别人（或其他页面）的改动。
- SQLite 数据文件放在 Docker 卷中，**容器重启 / 重建后工作稿、发布版、角色确认状态和改词建议（含处理结果）都保留**。

## 一条命令启动

沿用现有 Docker Compose 方式（无需额外服务或构建步骤；首次启动会自动建好包括改词建议在内的全部表）：

```bash
docker compose up --build -d
```

然后浏览器打开：

> **http://localhost:8000**

停止：`docker compose down`（加 `-v` 会连数据卷一起删除，慎用）。镜像更新后再次 `docker compose up --build -d` 会自动补齐新表，旧工作稿 / 发布版 / 确认与建议数据保留在 `rehearsal-data` 卷中不丢。

首次启动会自动写入一段原创的示例小场景（3 个角色、7 句台词、1 条示例笔记），并已冻结发布为 **r1**，三个角色对自己角色页在 r1 的所见内容也都处于「已确认」状态，方便直接体验「改稿 → 角色待确认 → 重新确认 → 再发布 r2 → 旧版 r1 仍可打开」。

## 角色确认与发布（操作流程）

1. 打开首页（`#/`），在**角色确认清单**里查看当前每个有台词角色的状态：
   - ✔ **已确认 rN**：该角色角色页当前所见内容与 rN 时确认的一致；
   - ⏳ **待确认**：从未确认，或确认过的内容已变化。点「去确认 →」直接进入该角色页。
   - 没有台词时清单为空，无需确认。
2. 在角色页（`#/role/角色名`）逐句核对：台词编号与顺序、正文、紧前提示、笔记。待确认时，与上次确认不同的句子会标出「正文已改 / 紧前提示已变 / 笔记已改 / 顺序已变 / 新增」等标签。
3. 点 **✔ 确认本页所见内容（rN）**：提交的是页面显示的所见修订号。
   - 期间有人改过稿（修订号过期）：**HTTP 409**，确认被拒，按提示刷新页面后重新核对、重新确认；确认成功**不会**推进工作稿修订号。
   - 确认只覆盖**本角色当时可见**的内容。其他角色页的改动（例如跟本角色无关的台词、不充当本角色紧前提示的句子）不会把已确认变成待确认。
4. 发布（首页「📷 发布当前修订 rN」）时，服务端在**同一个数据库事务**中依次核对：
   - 提交的修订号是否仍是当前修订（过期 → **409**，整次拒绝）；
   - 所有当前有台词角色是否都为已确认（有待确认角色 → **422**，响应 `pendingCharacters` 列出全部角色，整次拒绝，**不会留下任何部分发布版**）；
   - 该修订是否未发布过（重复发布 → **422**）；
   - 全部通过才把当前台词与笔记冻结为新发布版。
5. 已发布的旧版（含冻结的角色页、提示、笔记）始终可在首页打开；发布后继续改稿，旧确认状态不会被重置，但相关角色内容一变就会重新待确认。

> 确认状态保存在同一个 SQLite 数据库的 `confirmation` 表中（确认时所见内容的快照 + 所见修订号），容器重启后仍可查看。

## 改词建议（角色提出 → 编辑集中审阅）

1. **角色提交**：在角色页（`#/role/角色名`）自己的每句台词下都有「💡 改词建议」框，写好**拟替换正文**后点「提交改词建议（rN）」：
   - 建议只记录，**绝不直接改动工作稿**；提交时记录：台词编号、提出时的角色、提出时原文、拟替换正文、页面所见修订号。
   - 必须提交本页显示的所见修订号：期间有人改过稿（修订号过期）→ **HTTP 409**，建议未提交，刷新后重新提出；提交成功**不推进修订号**。
   - 只能对**当前属于自己**的台词提建议（台词已被改派 → 422 提示刷新）；拟替换正文为空或与原文相同 → 422/400。
   - 提交后该句台词下方会持续显示本句的建议及其状态（待处理 / 已采纳 / 已驳回）。
2. **编辑集中审阅**：顶部导航「改词审阅」（`#/review`），首页「改词建议」面板也会显示待处理数量并一键进入。每条待处理建议**并排显示三栏**：
   - **① 提出时原文**：角色当时看到的正文；
   - **② 当前正文**：工作稿此刻的正文（台词已删除则明确标出；改派后会标出现属角色）；
   - **③ 拟替换正文**：角色建议替换成的文字。
   - 服务端实时给出采纳预判：台词**已删除 / 已改派 / 原文已变**时标红提示冲突，采纳按钮禁用；这类建议只能核对后驳回，或请角色刷新后重新提。
3. **采纳（✔）**：只在台词仍在、现属角色仍是提出者、当前正文与提出时原文完全一致时才会成功。服务端在**同一个数据库事务**内：
   1. 把该台词正文替换为拟替换正文；
   2. 工作稿修订号 **+1**；
   3. 标记建议为「已采纳」（含采纳时的修订号与时间）。
   三步同时成功或同时回滚。台词已删除 / 改派 / 原文已变 → **HTTP 409（suggestion_conflict）**，**工作稿不变、建议保留为待处理**。**其他台词的改动、任何笔记改动、顺序 / 提示变化都不妨碍采纳**。
4. **驳回（✕）**：只把建议标记为「已驳回」，**不改动工作稿、不推进修订号**；台词已删除 / 改派 / 原文已变都可以驳回。
5. **后续联动**：采纳后正文变化（以及由此引起的紧前提示变化）会按既有规则把受影响角色变为「待确认」——首页确认清单会标出，全员重新确认前发布仍会被整次拒绝；角色页能看到差异标签。已处理的建议不能重复处理（再次采纳 / 驳回 → **HTTP 422**）。
6. **持久化与旧版**：建议和处理结果保存在同一 SQLite 数据库的 `suggestion` 表，**容器重启 / 重建后仍可查看**（台词被删除的建议也保留备查）；任何已发布版都不受建议及其采纳影响，**旧发布版保持原样**。

## 页面说明

| 页面 | 入口 | 能做什么 |
| --- | --- | --- |
| 首页 | `http://localhost:8000/#/` | 工作稿概览、**角色确认清单与待确认入口**、发布当前修订、打开各已发布版、改词建议待处理计数与审阅入口 |
| 编辑器 | `#/edit` | 增删 / 改派 / 改词 / 重排，一次保存为一个新修订 |
| 角色页 | `#/role/角色名` | 看本角色台词 + 紧前提示，写 / 改 / 清空笔记，**对自己的台词提交改词建议并查看处理状态**，**确认本页所见内容** |
| 改词审阅 | `#/review` | 并排显示**提出时原文 / 当前正文 / 拟替换正文**，采纳（含冲突提示）或驳回待处理建议，查看已处理历史 |
| 已发布全剧 | `#/pub/修订号` | 只读查看冻结快照（含冻结笔记） |
| 已发布角色页 | `#/pub/修订号/role/角色名` | 只读查看冻结的提示、台词与笔记 |

## 修订号与冲突规则（为什么不会互相覆盖）

- 工作稿有一个单调递增的修订号，任何成功的改动（编辑台词、保存笔记、**采纳改词建议**）都会让它 **+1**；**确认、提交或驳回改词建议不改动工作稿，因此不推进修订号**。
- 保存时必须带上当前页面显示的「所见修订号」（编辑、笔记、确认、**提交改词建议**、发布都一样）。服务端发现不是最新修订：
  - **HTTP 409**：整次拒绝，提示刷新；页面上的未保存改动 / 确认 / 建议不会悄悄覆盖别人的改动。
- 角色确认的有效范围只有该角色角色页所见的台词编号与顺序、正文、紧前提示、笔记：
  - 服务端在确认时存下这些内容的快照，之后逐字段比对；只有这些可见内容变化才重新变为待确认。
  - 其他角色的改动若不影响本角色的任何可见句子（含紧前提示），确认状态保持不变。
- 发布必须全员确认：
  - **HTTP 422（unconfirmed_characters）**：整次拒绝，`pendingCharacters` 列出全部待确认角色；冻结行在同一事务里回滚，不会留下部分发布版。
- 对带笔记的台词执行删除或跨角色改派：
  - **HTTP 422**：整次拒绝，响应里列出每条受阻台词编号、所属角色和处理入口；必须先去对应角色页清空或改写笔记。
- 采纳改词建议时，台词已删除 / 已改派给别的角色 / 提出建议后原文已被改动：
  - **HTTP 409（suggestion_conflict）**：工作稿不变、修订号不推进、建议保留为待处理；审阅页并排三栏会直接标出冲突，可驳回或请角色重新提。
- 已处理（已采纳 / 已驳回）的建议不能重复处理：**HTTP 422（already_decided）**。
- 一批编辑操作在**一个数据库事务**内提交，任何一条不合法则整批回滚，绝不出现「删了一半」。
- 笔记以台词编号为主键外键；编号由 SQLite `AUTOINCREMENT` 生成，删除后该编号也不会被新台词复用，因此笔记永远不会错挂。

## 数据持久化与备份

- 数据文件：容器内 `/data/rehearsal.db`（WAL 模式，另有 `-wal` / `-shm` 伴随文件）。
- 工作稿、笔记、发布版、角色确认与**改词建议及处理结果**都在这一个库里；表结构在启动时自动补齐（`CREATE TABLE IF NOT EXISTS`），升级镜像后旧数据卷可直接继续使用。
- Compose 中由命名卷 `rehearsal-data` 承载。备份时先停容器，再复制整个数据目录：

```bash
docker compose stop
docker run --rm -v rehearsal-script_rehearsal-data:/data -v "$PWD":/backup \
  alpine tar czf /backup/rehearsal-backup.tgz -C /data .
docker compose start
```

## 不用 Docker 的本地运行

需要 Python 3.11+：

```bash
pip install -r requirements.txt
python app.py
```

访问 **http://localhost:8000**。数据文件默认在 `./data/rehearsal.db`（可用环境变量 `SCRIPT_DB` 改路径，`PORT` 改端口）。
删除该文件后重启会重新生成示例工作稿。

## 主要 API（便于调试 / 脚本对接）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/draft` | 工作稿（含每句紧前提示、笔记、修订号） |
| POST | `/api/draft` | 批量增删 / 改派 / 改词 / 重排，body 含 `revision`、`ops[]` |
| GET | `/api/characters/<角色名>` | 角色页（提示 + 笔记 + 当前确认状态 + 本角色的改词建议） |
| POST | `/api/characters/<角色名>/confirmations` | 确认本角色页所见内容，body 含 `revision`；过期 409、角色无台词 404 |
| GET | `/api/confirmations` | 确认清单：当前每个有台词角色的状态（无台词时为空数组） |
| PUT | `/api/lines/<编号>/note` | 保存 / 清空笔记，body 含 `revision` |
| POST | `/api/lines/<编号>/suggestions` | 角色提交改词建议，body 含 `revision`、`character`、`proposedText`；过期 409、台词不存在 404、非本人台词 422、与原文相同 422 |
| GET | `/api/suggestions?status=pending` | 改词建议清单（默认全部，可按 pending/adopted/rejected 过滤）；每条附当前正文与采纳冲突信息 |
| POST | `/api/suggestions/<编号>/decisions` | 处理建议：`{"action":"adopt"}` 或 `{"action":"reject"}`；采纳在同一事务替换正文 + 修订 +1；删除/改派/原文已变 409 且建议保留；已处理重复处理 422 |
| POST | `/api/publications` | 发布当前修订（冻结全剧 + 全部笔记）；有待确认角色时 422，`pendingCharacters` 列出角色 |
| GET | `/api/publications` | 发布版列表 |
| GET | `/api/publications/<修订号>` | 某一发布版全剧快照 |
| GET | `/api/publications/<修订号>/characters/<角色名>` | 某一发布版的角色页 |

> 本应用不含登录鉴权，设计上假定运行在可信任的本地 / 剧组内网环境。
